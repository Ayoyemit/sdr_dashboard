### SANKEY PIPELINE OPTIMIZATION (NOV 2025)
- **Scope:** `New_Dash.py` and `sankey_visualizer.py`
- **What changed:** Replaced per-pathway `DataFrame.copy()` + row-wise `apply` logic with vectorized NumPy/Pandas transformations that assemble only the required stage columns. All stages are now categorical, letting Plotly’s Sankey builder operate on dense integer codes.
- **Big O (before):** ~`O(S · N log N)` time and `O(S · N)` space per generation (`S` = number of stages, `N` = row count). Each pathway rebuild copied data, ran multiple sorted groupby operations, and recomputed the summary from scratch.
- **Big O (after):** ~`O(S · N)` time and `O(S + N)` space for a first render, collapsing to ~`O(1)` on repeats thanks to a session-level cache keyed by `(scenario, pathway)`. Vectorized stage construction avoids extra copies, and groupby uses categorical codes with `observed=True` to skip empty combinations.
- **Why it’s faster:** 
  - Eliminated redundant DataFrame materialization and Python-level loops.
  - Categorical encoding makes count aggregation linear in the number of rows.
  - Cached Plotly figures and summaries short-circuit regeneration when users toggle pathways or revisit scenarios.
  - Added runtime instrumentation so each render reports elapsed time and cache hits, making performance transparent during demos.
